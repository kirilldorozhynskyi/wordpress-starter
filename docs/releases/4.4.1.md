# WordPress Starter 4.4.1

## Inertia and SSR

- Updated Inertia WordPress to 0.9.0. The starter registers the new SSR gateway and WordPress response emitter. SSR still reads the bundle from
  `wp-content/themes/inertia/resources/Private/.vite/ssr/ssr.mjs`. A missing bundle or an unavailable SSR server falls back to client-side rendering.
- Inertia visits with a stale asset version receive a 409 response with the current URL and asset version, so the browser reloads the page.
- The shared SEO prop uses a closure so client navigation continues to receive rendered metadata with Inertia's new callable resolution rules.

## Dependency updates

- Composer now requires WordPress 7.1.5 and ACF Pro 6.8.12 or newer within their existing major versions. The lockfile also updates MCP Connector
  to `32a171d` and Roave Security Advisories to `ea3fd42`.
- The npm manifest raises the minimum versions of Vue and its server renderer to 3.5.46 and Vue I18n to 11.4.23. The lockfile pins the updated versions.
- Plugin Update Checker stays on 5.7 because Inertia WordPress 0.9.0 and WP Vite currently require 5.x.

## Upgrade

Use PHP 8.4.28 or later in the 8.4 series, or PHP 8.5.13 or later in the 8.5 series, when installing the locked development dependencies. Use Node.js
26.13.1 or later in the 26.x series. Run `composer install` and `npm ci` from the project root. Follow the existing deployment instructions for client and SSR
assets. This release contains source and lockfiles.

## Verification

Lint, type checks, 16 frontend tests, and 12 Chromium tests passed. DDEV checks passed for the starter, simulated WPML, Gravity Forms, and public paths.
The site checks reused existing client and SSR assets. Additional HTTP checks verified a 409 reload response for a stale asset version and the client-side
fallback when the SSR bundle is missing.
