# WordPress Starter 4.3.0

Release date: 2026-09-24.

## Breaking changes

- PHP 8.4 or newer and Node 24 are required. DDEV and the production image use PHP 8.5.
- `inertia` is the only bundled theme. Legacy `template` and `test` themes are removed. Page metadata helpers now live in `InertiaTheme`; the root `JDEV` autoload mapping is removed.
- WP Sync DB and its media extension are replaced by Syncport. Media Cloud is no longer bundled. Existing installations must review their storage and migration setup before upgrading.
- Form submission no longer writes the language into hard-coded `input_13`. Project-specific hidden-field mappings must be configured explicitly.

## Changes

- Updated locked PHP and frontend dependencies; retained MIT PrimeVue 4.5.5 and themes 2.0.3 instead of the key-licensed major versions.
- Added Dokploy Compose deployment with PHP/Apache, Node SSR, MariaDB, persistent uploads/database volumes, Composer build secrets and healthchecks.
- Added process supervision and clean SIGTERM shutdown for Apache/SSR.
- Corrected production asset paths and MU-plugin inclusion in Docker builds.
- Refactored forms into typed feature modules, an HTTP service and accessible field components. Added request cancellation, retries for loading, duplicate-submit protection, conditional fields, date/file/consent serialization, validation and focus handling.
- Fixed internal-link classification for consistent server/client rendering.
- Made Composer installation preserve local environment settings and salts; explicit `composer setup` performs initial setup.
- Isolated request-sensitive data from shared caches and constrained news request size.
- Added regression tests, isolated form preview and deployment/frontend documentation.

## Upgrade

1. Back up the database, uploads and existing configuration.
2. Use PHP >=8.4 and Node 24. Run `composer install` and `npm ci` with access to private Composer packages.
3. Activate `inertia` if migrating from a removed theme; migrate custom code and content deliberately. This release does not migrate another theme's data automatically.
4. Configure Syncport and the application's mail/antispam services as needed.
5. For Dokploy, follow `docs/dokploy.md` and provide domain, database credentials, WordPress salts and Composer authentication through the deployment environment.
6. Use the committed production client/SSR assets, or rebuild explicitly with `npm run build` after source changes.

Composer repository refresh encountered a GitHub authentication failure in the local DDEV environment. Locked package versions are unchanged; only the root-version content hash was refreshed with Composer. Verify private Composer credentials before a clean install or deployment.

## Known boundaries

Uploads and database content are not distributed in Git. The local audit found missing scaled images/thumbnails for attachment IDs 194 and 197, with originals intact; regenerate these before migrating that local site's content. Real SMTP delivery, production antispam and multi-page/payment/CAPTCHA/compound-address/multi-file form integrations are not verified by this release.
