# Frontend: компоненты и формы

Активный исходный код: `wp-content/themes/inertia/resources/Private/js`. Единственная установленная тема — `inertia`; неактивные `template` и `test` вынесены из
проекта.

- `main.ts`, `ssr.ts`, `inertia.ts` — клиентский запуск, SSR и общая регистрация приложения. SSR не хранит состояние пользовательской формы между запросами.
- `pages/`, `layouts/` — страницы Inertia и каркас приложения.
- `components/` — интерфейс, props/model/events, доступность и работа с DOM.
- `features/forms/` — контракт Gravity Forms, нормализация, сериализация, условная видимость и composable управления запросами.
- `services/http.ts` — транспорт JSON и типизированная ошибка HTTP. Проверка результата конкретного API остаётся в feature.
- `util/` — существующие общие адаптеры PrimeVue, i18n и ссылки. Переносить их исключительно ради переименования не нужно.

Новый код использует Composition API, TypeScript на границах данных, `defineModel`, `useId`, `useTemplateRef`, AbortController и очистку lifecycle. Vue 3.5
используется в клиенте и SSR. Адаптивные изображения получают реальные URL и `srcset` в разметке, а отложенную загрузку выполняет браузер. Для первого экрана
используйте `loading="eager"` и `fetchPriority="high"` по необходимости.

## Адаптивные изображения

Глобальный `Image` использует `ImageWP.vue`. По умолчанию `sizes="100vw"` подходит для полноширинного Hero. Для колонок передавайте ширину изображения из
макета через `sizes`. Поле **Mobile image** задаёт отдельный кадр для экранов уже `48rem`, а `media` позволяет выбрать готовую пару размеров для других
брейкпоинтов.

WordPress регистрирует размеры `post`, `text_image`, `carousel`, `container` и их варианты `2x`. Для `size="full"` компонент передаёт доступные производные
с пропорциями исходника в `srcset`. Для именованного размера компонент использует соответствующий вариант `2x`, если он есть. При хранении в S3 компонент
использует URL исходника и производных, переданные WordPress.

```vue
<Image :image="photo" :image-mobile="mobilePhoto" sizes="(min-width: 64rem) 50vw, 100vw" />
<Image :image="photo" size="container" :media="{ 767: { size: 'carousel', size_retina: 'carousel2x' } }" />
```

Для старых вложений с сохранённым исходником можно создать отсутствующие производные командой
`ddev wp media regenerate <id> --only-missing --skip-delete`.
Для CDN-трансформаций импортируйте `ImgCdn.vue`.

Для видео ниже первого экрана задавайте `data-src` и `data-poster`, для декоративных фонов — `data-bg` и при необходимости `data-bg-hidpi`. Браузерный
загрузчик подхватывает эти атрибуты после монтирования Vue и при добавлении секций. Hero использует изображение как первый кадр и запускает видео после загрузки
страницы, когда секция видна.

## Публичные данные темы

В props отправляются поля, которые читает интерфейс. Новые публичные поля добавляйте через `inertia_theme/public_acf_fields`, поля секций через
`inertia_theme/public_acf_layout_fields`, глобальные опции через `inertia_theme/public_acf_options`. Для последнего фильтра передайте карту «slug страницы опций
→ список имён полей». Пароли, API-ключи и административные настройки храните на сервере. Защищённые паролем записи показывают штатную форму WordPress до
загрузки их контента.

## WPML

Theme Settings сохраняет страницу `theme_settings_default` с хранилищем `theme_settings` и языковые страницы с прежними `theme_settings_<код>` в качестве
slug и идентификатора хранилища. Группа ACF использует те же ключи на всех этих страницах. Для публичных настроек, объявленных на `theme_settings_default`,
берутся сохранённые значения текущего языка, а отсутствующие поля читаются из Default.

Переключатель использует URL из WPML. Словари интерфейса стартера включают английский и словацкий. Формы передают исходный языковой код WPML при чтении
и отправке, включая региональные коды. Проверка совместимости без установки WPML входит в `npm run test:project`.

## Формы

Стартер открывает посетителям определение и REST-отправку формы **1**. Для других публичных форм добавьте их ID через `inertia_theme/public_gravity_form_ids`.
Форма должна быть активна, а настройки Gravity Forms по-прежнему проверяются на сервере.

Публичный контракт сохранён: `<GForm :id="1" />`, поля используют `modelValue` / `update:modelValue`. Форма лениво загружается около viewport; при отсутствии
IntersectionObserver загружается на mount. Ошибки загрузки позволяют повторить запрос. Смена id/языка сбрасывает данные и отменяет старый запрос. Запросы
отправки автоматически не повторяются.

Успех определяется `is_valid === true`, а не только HTTP-статусом. Серверные ошибки связываются с полями через aria-describedby; фокус переходит на первое
ошибочное поле, а после успеха — на подтверждение. HTTP/HTTPS redirect из подтверждения поддерживается. Текст успеха локализован, произвольный HTML
подтверждения не вставляется.

Поддерживаются простые input/email/number/url, phone, date, textarea, select, radio, checkbox/multi_choice, consent, одиночный fileupload и HTML-блок. Date
отправляется в формате Gravity Forms. Скрытые значения берутся из определения формы; прежняя жёсткая запись языка в `input_13` удалена. Специфичные для проекта
UTM/объекты/язык следует добавлять через явный контракт, согласованный с реальными ID полей.

Многостраничные формы, платежи, составные name/address, множественная загрузка файлов и CAPTCHA требуют отдельных интеграций и здесь не заявлены как
поддерживаемые. Серверная валидация Gravity Forms остаётся обязательной.

## Что взято из «Балабенки»

- Стабильное определение внутренних ссылок по серверному URL сайта; в стартере это `wp.homeUrl`.
- Сопоставление checkbox по реальным sub-input ID и consent по подполью `.1` — сохранено и вынесено в тестируемый модуль.
- Явные состояния отправки и доступное сообщение результата.

Не перенесены проектные номера полей, стили с отсутствующими токенами, фиктивный Basic Authorization и отправка контактных данных в dataLayer.

## Зависимости и проверка

Тема использует Inertia 3 и VueUse 15. PHP-плагин EvoMark 0.8.5 отвечает за интеграцию с WordPress. Класс `InertiaRequest` и MU-плагин адаптируют его ответы к
протоколу Inertia 3. Команда `npm run typecheck` запускает TypeScript 7 для файлов TypeScript и `vue-tsc` для Vue-компонентов. ESLint и `vue-tsc` получают
классический JS API TypeScript 6 через пакет совместимости Microsoft.

Используются PrimeVue 5.0.5 и @primeuix/themes 3.1.1. Ключ PrimeUI Community записан в общей конфигурации `util/primevue-options.ts` с параметрами для клиента и
SSR. Vite включает этот браузерный ключ в клиентские ассеты. [Документация PrimeUI](https://primeui.dev/licenses/community).

```sh
npm run test:frontend
npm run lint
npm run typecheck
npm run preview:forms
```

Preview доступен только на `127.0.0.1:5174/tests/frontend/fixtures/forms.html`. Это отдельный стенд с подменённым API: имя `Invalid` воспроизводит ошибку
валидации; остальные значения — успешный ответ. Письма и реальные заявки не создаются. Тесты запросов проверяют гонки ответов, повторные отправки, retry и
unmount.

Перед деплоем выполните явно запрошенную production-сборку и включите её артефакты в коммит, как описано в `docs/dokploy.md`.

Источники API: [Vue v-model](https://vuejs.org/guide/components/v-model), [Vue helpers](https://vuejs.org/api/composition-api-helpers), установленный Gravity
Forms REST controller и date field.
