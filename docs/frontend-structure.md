# Frontend: компоненты и формы

Активный исходный код: `wp-content/themes/inertia/resources/Private/js`. Единственная установленная тема — `inertia`; неактивные `template` и `test` вынесены из проекта.

- `main.ts`, `ssr.ts`, `inertia.ts` — клиентский запуск, SSR и общая регистрация приложения. SSR не хранит состояние пользовательской формы между запросами.
- `pages/`, `layouts/` — страницы Inertia и каркас приложения.
- `components/` — интерфейс, props/model/events, доступность и работа с DOM.
- `features/forms/` — контракт Gravity Forms, нормализация, сериализация, условная видимость и composable управления запросами.
- `services/http.ts` — транспорт JSON и типизированная ошибка HTTP. Проверка результата конкретного API остаётся в feature.
- `util/` — существующие общие адаптеры PrimeVue, i18n и ссылки. Переносить их исключительно ради переименования не нужно.

Новый код использует Composition API, TypeScript на границах данных, `defineModel`, `useId`, `useTemplateRef`, AbortController и очистку lifecycle. Версия Vue остаётся установленной совместимой 3.5; номер года не является поводом менять рабочие API или добавлять state manager.

## Формы

Публичный контракт сохранён: `<GForm :id="1" />`, поля используют `modelValue` / `update:modelValue`. Форма лениво загружается около viewport; при отсутствии IntersectionObserver загружается на mount. Ошибки загрузки позволяют повторить запрос. Смена id/языка сбрасывает данные и отменяет старый запрос. Запросы отправки автоматически не повторяются.

Успех определяется `is_valid === true`, а не только HTTP-статусом. Серверные ошибки связываются с полями через aria-describedby; фокус переходит на первое ошибочное поле, а после успеха — на подтверждение. HTTP/HTTPS redirect из подтверждения поддерживается. Текст успеха локализован, произвольный HTML подтверждения не вставляется.

Поддерживаются простые input/email/number/url, phone, date, textarea, select, radio, checkbox/multi_choice, consent, одиночный fileupload и HTML-блок. Date отправляется в формате Gravity Forms. Скрытые значения берутся из определения формы; прежняя жёсткая запись языка в `input_13` удалена. Специфичные для проекта UTM/объекты/язык следует добавлять через явный контракт, согласованный с реальными ID полей.

Многостраничные формы, платежи, составные name/address, множественная загрузка файлов и CAPTCHA требуют отдельных интеграций и здесь не заявлены как поддерживаемые. Серверная валидация Gravity Forms остаётся обязательной.

## Что взято из «Балабенки»

- Стабильное определение внутренних ссылок по серверному URL сайта; в стартере это `wp.homeUrl`.
- Сопоставление checkbox по реальным sub-input ID и consent по подполью `.1` — сохранено и вынесено в тестируемый модуль.
- Явные состояния отправки и доступное сообщение результата.

Не перенесены проектные номера полей, стили с отсутствующими токенами, фиктивный Basic Authorization и отправка контактных данных в dataLayer.

## Зависимости и проверка

Используются PrimeVue 4.5.5 и @primeuix/themes 2.0.3 (MIT). PrimeVue 5 и themes 3 требуют лицензирования и не включены в универсальный стартер. [Официальное пояснение](https://primeui.dev/licenses/community).

```sh
npm run test:frontend
npm run lint
npm run typecheck
npm run preview:forms
```

Preview доступен только на `127.0.0.1:5174/tests/frontend/fixtures/forms.html`. Это отдельный стенд с подменённым API: имя `Invalid` воспроизводит ошибку валидации; остальные значения — успешный ответ. Письма и реальные заявки не создаются. Тесты запросов проверяют гонки ответов, повторные отправки, retry и unmount.

Перед деплоем выполните явно запрошенную production-сборку и включите её артефакты в коммит, как описано в `docs/dokploy.md`.

Источники API: [Vue v-model](https://vuejs.org/guide/components/v-model), [Vue helpers](https://vuejs.org/api/composition-api-helpers), установленный Gravity Forms REST controller и date field.
